# AD-LAB - Self Run

## What is being conducted
This lab is a personal attempt to gain skills in active directory and virtualisation, concepts that I am very unfamiliar with but hope by the end of the lab I can traverse directories and user permissions from an admin perspective. The lab itself uses my gaming pc as a headless virtualisation host which is remote accessed from my macbook. To achieve this I have set-up Proxmox onto the computer and used a travel router to make a network in which my computer and macbook can communicate. 

## Session 0 -  Physical Setup
During this session I arranged for my computer to sit elsewhere from my workspace and plugged it up with a monitor and the travel router. I chose this method due to that computer having the most power to comfortably run the most virtualised hosts with the smoothest experience. I initialised virtualisation through the bios before putting in a usb with Proxmox (Proxmox 9.2) loaded beforehand to override windows. Upon initial boot of proxmox, I aligned the IP address, DNS and gateway values to what comes preset in my travel router (GL-SFT1200). After connecting both my macbook and computer to the sub-network of my travel router, I was able to directly interact with the Proxmox on the computer through my macbook and even shutdown the computer remotely by running "shutdown -h now" which I found really interesting but also scary from a security perspective. 

### Mistakes and Issues
After initial setup I left the usb in the computer which made it recognise a foreign boot device and I had to set it up all over. This happens due to a computers natural boot order and it picking up a foreign device as the desired boot device if it contains a boot image. The mistake cost 5 minutes to re-do initial proxmox settings, which is a reminder next time to check all ports in the front panel and I/O panel before any boot.

Upon trying to connect to the host computer initially, I ran into the issue where Chrome would not let me access the site due to it not being trusted. I tried another web browser which was Safari which worked straight away. This made me realise that the settings for Chrome had stopped me from proceeding to untrusted websites where the domain had no Certificate Authorities vouching for it's identity. In this instance I allowed Chrome to proceed and it is a simple permission which can be enabled from device settings which runs after a simple application restart. In the case of everyyday users, I would not recommend turning off this saftety setting. This is because this is a server I know and is in my own private network, I would never recommend the same settings on the open internet.
